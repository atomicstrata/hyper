# Method and limits

These are exploratory measurements on one Mac, collected on October 3, 2026. They inform positioning and roadmap work. They are not a universal speed ranking, a human usability study, or release guarantees.

## Machine and execution

Apple M5 Pro, 15 CPU cores, 16 GPU cores, 24 GiB RAM, macOS 27 arm64; Rust 1.89, release builds, CPython 3.12, Node 24.16.0. Browser evidence records the actual Chromium revision and ANGLE Metal renderer. Hyper uses Bevy 0.18.1 and Metal. Low power mode is off. Power-source reporting says AC while the battery reports discharging. Thermal telemetry was unavailable. A late checkpoint confirmed display sleep is configured off and idle display/system sleep assertions are active. Ordinary desktop background load and variable display refresh were not controlled.

Tracks run sequentially, without another benchmark or compilation running. Tool/dataset order is randomized with seed `20261003` inside each repetition. Tracks themselves run in blocks; block order is not randomized. Report medians of five per-run measurements, with per-run p95 ranges where available. Quantiles use linear interpolation. Average FPS is sample count divided by total elapsed interval time; it is not the inverse of median frame time.

## Inputs

`scripts/benchmarks/datasets.py` produces native JSON, HIF, explicit bipartite incidence JSON and a shared synthetic update for each dataset. The manifest records every file's SHA-256, counts and provenance. Fixed seeded XYZ coordinates are shared; 2D tools use XY. Native geometry uses `f32`, with corresponding numeric rounding. Layout quality is not tested by frozen-coordinate rendering.

## Tracks

**Scientific figures:** pinned HyperNetX 2.4.3, XGI 0.10.2, Hypergraphx 1.8.0, Matplotlib 3.11.2 and Pillow 12.3.0. Each observation uses a fresh process, with a discarded warmup and five repetitions. Imports, file read, JSON parse, canonical validation, library construction, artist setup, Agg rasterization, pixel copy and PNG compression are separate stages. Top-level scientific library imports and common Matplotlib/Pillow initialization are not charged to construction. The artist stage includes the public drawing call and any lazy drawing-module initialization. Figures are 1920 × 1080 at 100 dpi, with labels off and supplied XY positions. Hull/polygon algorithms differ: HNX uses rubber-band outlines, XGI convex hulls, and HGX its default 12 Chaikin refinement rounds. Thus these are stock figure workflows rather than identical raster workloads. No large/stress plots are attempted outside the chosen correctness, moderate and Diseasome figure cases. Whole figure workers have a 120-second timeout.

Scientific metadata checks store original records as opaque attributes. HNX document metadata uses a custom graph attribute; HGX stores canonical edge IDs as metadata because its native identities are member tuples. Checks compare with independently parsed immutable source bytes and separately flag native node/edge identity loss. These model checks do not establish each library's own file-export fidelity or GUI inspection behavior.

**Browser incidence rendering:** pinned 3d-force-graph 1.80.1, Cytoscape.js 3.34.3, Sigma 3.0.3 and Graphology 0.26.0. The browser is headed, with 1920 × 1080 content and DPR 1. Every node, empty-edge hub and incidence is supplied without sampling. Labels and physics are off. Each repetition has 120 warmup callbacks and 300 recorded callbacks, with scripted camera/redraw movement. A 90-second per-job budget covers load, validation, warmup, sampling, update and evidence capture. An exceeded budget is not a measured per-frame duration. Partial failures are saved and pages closed before continuing.

3d-force-graph uses perspective spheres, resolution 8, radius parameter 2 and thin lines. Its public Three.js renderer is invoked directly with animation/interaction disabled. Sigma uses WebGL 2D and its public `scheduleRender` cached redraw path; Cytoscape uses Canvas2D and schedules redraw through `forceRender`. Their JavaScript command times represent different submission paths. rAF intervals represent callback cadence, without GPU completion or presentation timestamps. Native vs browser cadence also depends on vsync. The corrected Sigma block showed roughly 16.7 ms callback intervals on smaller cases, versus roughly 8.3 ms in some original Cytoscape cases. The browser version and machine were unchanged, but display cadence was not locked; callback-rate ratios across these blocks cannot establish engine efficiency. Three.js counters describe the last render submission; GPU duration and browser peak RSS are unmeasured.

**Hyper core:** fresh optimized processes, five solver warmup steps, then 20 recorded steps, plus one discarded process run per dataset. Native parsing, offline HIF parsing/schema validation, viewer conversion, bipartite projection and all-group CPU hull construction are independent operations. HIF document round trips and projection memberships are verified. Hulls cap geometry at 24 selected vertices, so high-arity surfaces are approximate. The combined worker retains multiple documents for correctness checks; its RSS is not the memory needed for one parsed document.

**Hyper native rendering:** the opt-in `benchmark` feature invokes the production renderer. Fixed input positions replace automatic startup layout. The window is physical 1920 × 1080, DPR 1, AutoVsync, 120 warmup frames and 300 recorded frames per fresh process. All links are enabled, with native line opacity 0.10 (browser line opacity is 0.35). HUD and picking systems remain installed; scripted orbit replaces camera input. Basic modes disable labels. Hull modes use ordinary filled hulls, no wireframe, with the 24-vertex cap. Live modes take one timed layout step per frame; frozen modes take none. Live hulls use production skinning between topology rebuilds every eight frames. A solver-iteration assertion rejects extra untimed steps. The stock viewer normally uses a different step count, so this is an explicit benchmark setting. Bipartite incidence and Mathlib's star/group mode are separate representations. In star mode, dyadic groups render pair lines, despite having no incidence links or spring edges in the scene model. Its live layout therefore performs different force work from bipartite layout. Star without hulls is an ablation: larger groups have no surface geometry. It cannot be treated as an equivalent full-group rendering score. Default label-enabled modes are separately identified. Their Capped policy uses a graph-count threshold of 250, with selected/hovered exemptions; it does not draw every label on these larger inputs.

Native intervals are CPU application frame boundaries, including pipeline waits, rather than GPU duration or verified presentation. A scene replacement uses the shared 1% update in memory, excluding file-watch polling, I/O and parsing. Commit time and the next application interval are reported separately. The shared update changes 1% of groups, but adapter commit strategies differ: Cytoscape updates all supplied node data/positions and edge endpoints, Sigma diffs its Graphology records then performs a full geometry refresh, 3d-force-graph replaces its graph data, and Hyper replaces its scene while preserving positions. These timings describe the current public-API integrations and can include unchanged-record work; they do not isolate an optimal incremental algorithm. Browser update feedback is a two-rAF surrogate. Neither is hardware input-to-visible latency. RSS uses macOS `/usr/bin/time -l`, includes startup, and includes benchmark-retained source/update data and correctness work. These memory scopes differ between tracks.

## Remaining limits

Human task accuracy, perceptual ambiguity, layout convergence, actual input-to-visible latency, GPU timestamps and cross-platform performance remain unmeasured. Picking is installed in the native viewer, but no controlled hover/click study is performed. Frozen coordinates do not assess the readability of each tool's automatic layout. Metadata retention by an adapter is distinct from attribute inspection in the product.

Graphia import/save and HyperGodot group drawing have separate adapters and representations. HyperGodot uses stock HiDPI and verifies its physical render texture at 1920×1080 (screen scale 2). The earlier HiDPI-disabled 1920×917 clamped-window run is an excluded diagnostic. Hyper requests 1920×1080 physical pixels and an untimed native screenshot verified that render size; individual native runs do not record an additional render-target size query. Graphia GraphML retains the incidence topology, roles, original IDs, arbitrary `attrs` and XYZ attributes, but omits document metadata and native top-level display fields (label/kind/status/weight). This is not a complete HIF-document round trip. Its GraphML stores XYZ as attributes; the tested headless path does not establish common render coordinates. HNX Widget cannot freeze its edge-hub positions through the reviewed public interface. HGPolyVis's supplied executable requires Windows. Julia's runtime was verified, but optional Julia package timings are absent. PAOHVis needs a temporal dataset/task. Gephi and egui_graphs remain references outside this automated rendering harness.

Native whole-batch timeouts also occurred on a small fixture, so they are unresolved runtime/workflow failures, not proof of a graph-size capacity boundary. Completed frame traces remain conditional on completion. Diagnostic and discarded driver runs are excluded from published summaries. No competitor implementation is optimized or altered to improve scores. HyperGodot's disposable copy removes an unused autoload whose referenced resource is missing; that packaging repair and its coordinate instrumentation are recorded explicitly.

## Source-audit follow-up

`animation::node_motion` searches the entire hyperedge list for each hub, and `render::update_node_positions` calls it for each node. This is a confirmed quadratic lookup path as group count grows, including hidden hub entities. `GraphLayout::hub_status` already provides an indexed cache. This is a concrete profiling/refactoring candidate; timing attribution to that path has not been isolated, and production code was left unchanged for the benchmark baseline.
